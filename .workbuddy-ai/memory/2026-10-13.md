## 抽卡页食材卡片：插画被裁 + 白描边（第二轮）

用户反馈两条：「食材图片太大导致卡片很不协调，缩小」「图片被切割，修复一下」「文字加白描边，显得可爱」。

### 根因：`sm:` 视口断点 vs 恒定 410px 手机壳
应用恒渲染在 `max-w-[410px]` 手机壳里，但抽卡页网格用了 `sm:` —— 而 `sm:` 看的是**视口**宽度：

| 视口 | 列数 | 卡片 | 结果 |
|---|---|---|---|
| >640px | 3 列 | 99~106px | 卡片内 `sm:` 尺寸全部生效（p-2 / badge h-5 / 菜名 11px），
把中间图槽压到 **29px**，而图是 `sm:w-[86px]` → 被 `overflow-hidden` 裁掉 |
| <640px | 2 列 | 176px | 图 76px 只占 43%，一屏 4 个，太散 |

**同一份代码在两种窗口宽度下是两个样子。** 这是全项目第一类结构性问题：
`sm:` 在固定宽度容器里全部是错的。

### 改法
1. `grid grid-cols-2 sm:grid-cols-3 gap-2.5 sm:gap-3` → `grid grid-cols-3 gap-2.5`
2. **卡片内部一律去掉 `sm:` 变体**（p-2 / rounded-18 / badge h-5 / text-13px /
   checkmark w-4 / border-1.5px / 菜名 11px / kcal 9px / 价格 9.5px），统一用移动端值
3. 外层 `p-3 sm:p-4`、`px-0 sm:px-1`、`mt-3.5 sm:mt-4.5` 同样去掉 `sm:`
4. 插画尺寸改成 `h-full w-auto max-w-full object-contain`
   —— **不能用固定 px**：图槽高度随卡片宽度变（106px 卡片 → 槽 43px；
   114px 卡片 → 槽 51px），固定值必有一边被裁。`h-full` 让图吃满图槽。

改完实测：vw=1400 → 卡片 106、插画 43、图槽 43；vw=500 → 卡片 114、插画 51、图槽 51。
两种视口都 3 列、都不裁，插画占卡片 41~45%（与原 2 列 76/176=43% 一致）。

### 白描边
新增 `src/index.css` 的 `.text-stroke-white`，用 **8 向 `text-shadow`**，
不用 `-webkit-text-stroke` —— 后者是**居中描边**，会吃掉字形内部，
粗黑体加 2px 后笔画明显变细；text-shadow 只向外扩，才是「贴纸外描边」的观感。

⚠️ **只在青柠底/彩色底上有效**。实测加在食材卡片文字上：
- R / SSR 徽章（青柠底 / 金底）→ 白描边**清晰可见** ✓
- 价格胶囊 `¥2`（青柠底）→ **可见** ✓
- 菜名（卡片底 `#f7f9fb`）、kcal（`#f1f4f8` 胶囊）→ **基本看不见**

给用户说明了这一点，浅底文字若要有描边得换深色描边或加深底色，等反馈。

### 新增脚本
`scripts/probe-card-fit.mjs` —— 两种视口（1400 / 500）校验卡片列数=3 且插画不被裁，
有失败项则 exit 1。

## 菜名压在插画上 + 描边加粗（第三轮，用户澄清）

用户澄清第一轮的白描边需求：「我说的不是 R SSR 加白描边，是**食物名字**加白描边，

**关键领悟**：用户要的不是「给文字加白描边」，而是「**菜名压在食材图上**」——

只有把菜名搬到插画上，白描边才有存在的意义。**下次遇到「浅底上加白描边」的需求，
先问自己是不是该把文字挪到彩色/图片背景上。**

### 改法
1. `<h4>` 从卡片流中（图槽之后）搬进**图槽内部**，`absolute inset-x-0 bottom-0 z-10`
   + `pointer-events-none`（不挡卡片点击）
2. 字号 `text-[10px]` → `text-[12px]`
3. 描边换 `.text-stroke-white-lg`（2px）—— 新增，见 `index.css`。
   1.5px 描边配 12px 字偏细，压不住底下的插画
4. ⚠️ **图槽加 `max-h-[50%]`**：菜名搬走后少了一行的高度，会被 `flex-1` 全吃掉，
   插画凭空胀大（43px → 59px）。用 `max-h-[50%]` 锁住上限，实测图 46px，与原来 43px 基本一致。

### 实测（vw=1400）

### 第四轮：遮挡太多，插画上移
用户反馈「挡住部分太多了，适当把食材向上移动一点」。

**我上一轮写在这儿的解法是错的**，别照做 —— 当时以为「调大 `max-h-[50%]` 让插画更高、
菜名占比自然下降」。实际上调大 max-h 只会让插画**变大**（撞用户「图片别太大」的底线），
插画底缘仍贴槽底，与菜名**重叠的绝对像素数一点没少**（都是 15px）。
遮挡比例下降只是因为分母变大了，是假象。

**正确解法：给图槽加 `pb-2`（8px）。**
插画 `h-full` 量的是**内容盒**高度，所以这 8px 会直接从插画高度里扣掉：
46 → 38px，且插画贴内容盒顶部 → **整体上移**，重叠 15px → 7px（占插画高度 33% → 18%）。

**通用规律**：要让「压在元素 A 上的文字 B」少挡 A，不能放大 A，
要给 A 所在容器留出**等于 B 高度的下边距**（`padding-bottom`），A 的高度会自己让出来。
调遮挡量只需改这一个值。

### 第九轮：详情页插画替换动画「下砸」改柔和
用户：「这个页面中选择不同的会有下砸的替换效果」（截图 = `ProductDetailPage`）。
追问确认：指**顶部插画替换**，要**改柔和**。

**根因在 `AnimatePresence mode="wait"`**（`ProductDetailPage.tsx` 顶部插画区）：
`mode="wait"` 是「旧图先退完 0.22s，新图才开始进 0.22s」→ 中间约 0.22s 画面**全空**，
然后新图带着 `initial={{ scale: 0.88, y: 8 }}` 从下方放大砸出来。
「空一下再砸出来」就是用户说的下砸感。

**改法**：
1. 去掉 `mode="wait"` → 默认交叉淡化，新旧同时过渡，没有空档
2. 位移/缩放收小：`y 8→3`、`scale 0.88→0.96`；exit `y -4→-2`、`scale 0.92→0.98`
3. 时长 `0.22 → 0.26`
4. ⚠️ **关键副作用**：去掉 `mode="wait"` 后两个 `motion.div` 会同时在 DOM 里，
   父级原本是 `flex items-center justify-center` → 会把新旧图**排成左右并排**。
   解法：父级改 `grid place-items-center`，子级加 `col-start-1 row-start-1` 强制同格叠放。
   **不要用 `absolute inset-0`** —— 那会吃掉父级的 `pt-6/pb-2`，插画整体下移约 8px。

验证：切换瞬间新旧 svg 中心位置一致（旧 `632,91` / 新 `626,89`），确认是叠放不是并排。

**通用教训**：`AnimatePresence mode="wait"` 适合「必须等旧的走完」的场景（如整页切换），
但只要新旧元素**能叠在一起**，交叉淡化几乎总是更柔和的选择。
用它的代价是必须自己解决「两个元素同时在流里」的排布问题。

交付：`outputs/detail-swap/detail-swap-soft.mp4`（录屏，含 5 次规格切换）。

4. 正确判据：`gridW > 340` **且连续两次采样相同** → 拿到稳定态。

`5×62 + 4×10` × `2×62 + 18` 的期望值。

**真正的根因**：`revealAnchor` 用「**视口**高 × 0.46」，而手机壳是
**顶部对齐（justify-start）+ 固定高度**（宽视口 844px / 窄视口 100dvh）。

实测（手机壳恒为 y=24 h=765，中心 406）：

| 视口高 | 锚点 y | 实测网格中心 | 相对手机壳中心 |
|---|---|---|---|
| 900 | 414 | 415 | +8px（看不出） |
| **1200** | 552 | 552 | **+145px** |
| **700** | 322 | 322 | **-85px** |

x 方向一直是对的（手机壳水平居中 == 视口中心）。

**修法**：锚点改用**手机壳的可视矩形** ——
从 `#gacha-page-root` 往上找第一个 `overflowY: auto|scroll` 的祖先，取它中心 x、46% 高 y。

## 抽卡揭示：顶部提示胶囊压住稀有度徽章（第三次踩「视口中心 ≠ 手机壳中心」）

用户：「像这张卡片抽到食材提示挡住卡片的稀有度了」。

### 根因：参考系不一致
`GachaBurstReveal` 里，结果卡锚在 `revealAnchor`（= **手机壳**可视区中心，
从 `#gacha-page-root` 往上找第一个可滚动祖先量出来的）；
而顶部提示胶囊（「✨ 抽到 N 款食材」）写的是 `top: calc(50% - 190px)` ——
覆盖层是 `fixed inset-0`，`50%` 是**视口**高的一半。手机壳顶部对齐 + 高度固定，
视口一变两者就错开。

写 `scripts/probe-reveal-pill.mjs` 复现（单抽/十连 × 视口 700/844/900/1200）：

| 视口高 | 卡片中心(壳) | 胶囊(视口50%-190) | 结果 |
|---|---|---|---|
| 700 | 298.7 | 160 | 重叠 21.8px |
| 844 | 364.9 | 232 | 重叠 **36.9px**（用户截图这档） |
| 900 | 370.3 | 260 | 重叠 17.1px |
| 1200 | 370.3 | 410 | 不重叠，但掉进卡片里压住插画 |

### 修法
`style={{ top: revealAnchor.y - (mode === 'single' ? 190 : 148) }}`

- 单抽：卡高 226.5 → 卡顶 = 锚点-113；徽章上凸 14px → 徽章顶 = 锚点-119；
  胶囊高 40px + 留 31px 间隙 → `锚点-190` ✓
- 十连：最高一排徽章顶 = 锚点-77（网格 2 行、行距 80、卡高 62）→ 同样留 31px → `锚点-148`
- ⚠️ 十连原来写 208（配 `50%` 用）。**换参考系后必须同步改** ——
  沿用 208 的话间隙会从原来的 ~16px 变成 91px，提示飘到半空。
  这是「修一个 bug 带出另一个视觉变化」的典型，改参考系时要顺手重算所有相对偏移。

复测：8 组（2 模式 × 4 视口）全部 ok，间隙恒为 **31px**，重叠 0。
`scripts/shot-reveal.mjs` → `outputs/reveal-pill/{single,ten}-vh{844,1100}.png` 目视确认
（单抽 SSR 徽章完整露出、十连 10 枚 R/SR/SSR 徽章全部可见）。

### 探针踩的坑（写下来免得再犯）
1. **`measure()` 里的卡片选择器必须按模式取**：单抽 `data-reveal-card="single"`，
   十连 `data-reveal-card="ten"`（10 张）。写死 `"single"` 会让十连永远测到 null，
   报「十连揭示卡没出现」—— 实际十连 t=2.5s 就出卡了，白查了一轮。
2. **必须等入场 spring 收敛再冻结 rAF**：卡片 initial `scale: 0.2` → spring 收敛前量到的
   卡高只有 208px（收敛后 226.5px），用缩放中的矩形算重叠会算错。等 550ms 安全
   （单抽 揭示→起飞 有 920ms 窗口）。
3. 十连时间轴：`active` 后 380ms 出卡 → 1650ms 起飞 → 2800ms 退场；
   页面侧还有 2000ms 的餐盖动画接管延迟。
